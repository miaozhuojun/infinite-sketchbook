# 独立审片评分表

> 给独立审片 agent 用。审片人与制作无关，只读不改。程序检查已经保证"不出错"（见流水线报告）；这里只判断**好不好**：好不好看、学不学得懂、留不留得住人、每个画幅是否恰到好处。
> 每条问题都必须写清**该在哪一层修**，这是三层分工能闭环的关键。

## 材料

- `out/<id>/{9x16,16x9,1x1}.mp4`：成片（审片 agent 看不到运动、听不到声音，只看帧，如实说明）
- `out/<id>/preview_{9x16,16x9,1x1}.png`：设备预览（手机 / 笔记本 / X 卡片，平台界面为示意）
- `out/<id>/review/*.png`：按帧号精确抽取的联系表（格子里标帧号和时间）
- `out/<id>/report.md`：程序检查和自动修正记录
- `out/library/preview.png`：组件库预览（判断组件本身的美感）
- 分镜 `data/<id>.beats.json` 里的 `brief`（学习目标）

## 全量审片和增量审片

- **全量**：第一版、准备交给用户的候选。按下面的要求逐秒抽帧、全片看完。
- **增量**：中间几轮。制作方给你上一轮的审片 JSON 和这一轮改了哪些时段（按新时间线的秒数）。只做三件事：上一轮每条问题现在是改好了、改了一半还是没改；改动的时段前后各多看 3 秒，找新问题；其余部分每 10 秒抽一帧扫一遍，看有没有被连带弄坏。分数按全片给，问题清单只列这次看到的。

## 维度与打分（1–10，10 = 同类头部水平）

| 维度 | 看什么 |
|---|---|
| 审美·画面 | 构图与留白、字形（儿童手写气质但精良）、线条质感、配色克制、铅笔真实感、风格是否统一 |
| 审美·镜头与节奏 | 取景是否恰好、画面变化节奏、关键处是否给了停留 |
| 教学 | 学习目标里的每一条，画面上有没有对应的动作；类比是否帮理解；有没有具体例子；有没有歧义；从一个例子换到另一个（尤其是观众不熟悉的）时，有没有先接上、说清新例子里的东西各是什么；留给下一集的，是说成了一个清楚的问题（悬念），还是让人没看懂（一头雾水）——后者按「重要」报 |
| 吸引力 | 开头 3 秒有没有钩子、多久一个顿悟、结尾有没有让人想看下一集（片段可注明不适用） |
| 画幅适配 | 每个画幅各自是否恰到好处：主体大小、字的可读性、平台界面避让、不是"同一张图换个框" |

## 评分锚点

每个维度按下面的锚点打分，先数问题、再判断：分数跟着这个维度上的问题走，不凭整体印象。

| 分数 | 这个维度上 |
|---|---|
| 10 | 和同类头部作品放在一起看不出差距；挑不出问题 |
| 9 | 没有阻断、没有重要；次要最多 2 条，正常观看时注意不到 |
| 8 | 没有阻断、没有重要；次要 3–5 条，或有 1 条正常观看时会注意到 |
| 7 | 没有阻断；最多 1 条重要 |
| 6 | 2 条以上重要 |
| ≤5 | 有阻断 |

- 一条问题只算在它最影响的那个维度上，不重复扣分。
- 上一版指出、这一版没改的问题，严重程度不降，并在 `previous` 里标「未解决」。
- `overall` 取五个维度的平均，保留一位小数。
- 「同类头部」指 linvo、老肉这一类讲解视频的完成度。没有对照它们的成片看，就不要写成和它们比较过的结论，只写按锚点判断的结果。

## 每条问题的写法

```json
{
  "severity": "阻断 | 重要 | 次要",
  "target": "9x16 | 16x9 | 1x1 | all",
  "frame": 1234,
  "symptom": "看到了什么",
  "fix": "具体怎么改",
  "layer": "episode | library | style | gate"
}
```

`layer` 的含义：
- `episode`：这一期的分镜数据该改（布局、文案、画什么、什么时候画）。
- `library`：组件本身不好看或缺少表达能力，应该改组件或新增组件（附测试与预览）。
- `style`：风格规范的取值不对（颜色、字号阶梯、线宽、字幕、音量……），改了会影响以后每一期。
- `gate`：程序本该拦住却没拦住，应新增或加严一条检查（同时在 `qa/selftest.mjs` 加注入用例）。

## 输出

写成 `out/<id>/review/review.json`：`{ "scores": {维度: 分}, "overall": 分, "issues": [...], "coverage": "看了哪些、没看到什么" }`，并附一句话总评。
